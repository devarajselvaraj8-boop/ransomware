# Early-Stage Ransomware Detection via Dynamic Memory Analysis and Reinforcement Learning

A comprehensive, reproducible defensive machine learning and reinforcement learning research pipeline designed to detect ransomware behavior before catastrophic file encryption occurs.

> [!IMPORTANT]
> **Defensive Cybersecurity Mandate:** This project is strictly for defensive threat detection and academic malware analysis research. It contains **no live malware binaries, payloads, exploits, persistence mechanisms, or encryption routines**. All experiments operate exclusively on sanitized dynamic sandbox execution traces and mathematically validated synthetic multi-window temporal telemetry.

---

## 1. Project Overview

Ransomware remains one of the most destructive threats in modern cybersecurity. Conventional machine learning detection systems typically rely on post-execution cumulative telemetry summaries generated by dynamic sandboxes (e.g., Cuckoo Sandbox). While static classifiers trained on these summaries report near-perfect test accuracy, they detect infections **too late**—after hundreds of files have already been permanently encrypted and ransom notes have been deployed.

This research project introduces an end-to-end framework that bridges the gap between post-execution static classification and sub-second pre-encryption threat detection:
1. **Static Baseline Auditing:** Demonstrates the ceiling performance and pitfalls of cumulative sandbox features.
2. **Early-Stage Feature Pruning:** Proves that pre-encryption Win32 API calls and dynamic memory allocation retain >99% discriminative signal when destructive filesystem artifacts are removed.
3. **Multi-Window Temporal Pipeline:** Constructs a strictly causal, multi-window telemetry schema ($W_0 \to W_4$) modeling the temporal evolution of malware execution.
4. **Proximal Policy Optimization (PPO):** Casts early detection as an optimal stopping problem, training an RL agent to trade off observation latency against classification risk.
5. **Interactive Research Dashboard:** Provides real-time visual telemetry inspection and episode replay capabilities.

---

## 2. Research Objective

The core objective is to formulate and validate an early-stage detection paradigm capable of identifying ransomware processes during initial execution windows (e.g., 0–5 seconds post-spawn) before irreversible filesystem damage occurs.

Specifically, the project investigates:
- To what degree do static classifiers rely on cumulative post-encryption indicators (e.g., `file_created`, `file_deleted`)?
- Can early memory allocation behaviors, thread creations, and cryptographic API imports predict ransomware families prior to mass writes?
- How does an autonomous reinforcement learning agent (PPO) optimize the decision threshold between collecting additional evidence and halting execution?

---

## 3. Architecture & Methodology

The system architecture spans two primary paradigms:

```
[ Dynamic Sandbox Traces ]
          │
          ├──> [ Static Pipeline ] ──> Feature Pruning (16 Early Feats) ──> Static RF & XGBoost
          │
          └──> [ Temporal Pipeline ] ──> Multi-Window Causal Aggregation ──> Temporal RF & XGBoost
                                          │
                                          └──> [ Gymnasium MDP ] ─────────> Temporal PPO Agent
```

### Telemetry Domains & Observation Windows
Telemetry is partitioned into 5 discrete, sequential observation windows:
- **$W_0$ (0–2s):** Process creation, PE loading, initial memory allocations.
- **$W_1$ (2–5s):** Cryptographic library loading, registry key enumeration, mutex acquisition.
- **$W_2$ (5–10s):** Directory traversal, volume queries, shadow copy tampering.
- **$W_3$ (10–20s):** High-velocity file modifications and bulk payload encryption.
- **$W_4$ (20–30s):** Ransom note creation, desktop background modification, C2 communications.

### Causal Feature Engineering
All temporal statistics at window $t$ are computed strictly over historical windows ($\tau \le t$). Zero future lookahead ensures zero data leakage.

### Reinforcement Learning Formulation (MDP)
- **State ($S_t$):** 60-dimensional causal feature vector concatenated with current window index $t$.
- **Actions ($A$):**
  - `0 (CONTINUE_MONITORING)`: Pay minor time penalty ($-0.05$), observe next window.
  - `1 (SUSPICIOUS)`: Flag process for forensic snapshot ($-0.02$).
  - `2 (RANSOMWARE_ALERT)`: Issue emergency quarantine; terminate process.
- **Reward Function:** Time-decaying alert rewards ($+10.0 \cdot (1 - 0.15 \cdot t)$), severe penalties for false alarms ($-10.0$) and missed detections ($-15.0$).

## 11. Research Limitations & Defensive Safeguards

### Defensive Safeguards
- **Zero Binary Execution:** The pipeline analyzes structured telemetry only; no malware samples are executed.
- **Input Sanitization:** The dashboard accepts only numerical feature matrices conforming to the validated schema.

### Methodological Limitations
1. **Synthetic Multi-Window Telemetry:** The temporal telemetry dataset is synthetically generated to validate pipeline architecture and causal algorithms. It should not be cited as real-world detection proof.
2. **Post-Execution Feature Inflation:** High baseline accuracy on cumulative sandbox features reflects post-encryption states rather than real-time defense.
3. **Absence of Hypervisor VMI Traces:** Hardware-level memory access patterns (e.g., page-table entropy, sub-millisecond call graphs) are not present in the static source dataset.
